# VoxBridge — Admin Playbook (ЗАКРЫТЫЙ ДОКУМЕНТ)

> ⚠️ Этот документ предназначен ТОЛЬКО для людей с ролью admin (Галина, Влад, Владимир).
> Не публикуется пользователям платформы, не упоминается в пользовательской документации.
> Последнее обновление: 28 июня 2026.

---

## Кто является админом и как

Роль администратора задаётся вручную — поле `role` в таблице `users` устанавливается в значение `admin` через панель Supabase (Table Editor), не через форму регистрации. Любое количество людей может иметь эту роль одновременно, каждый под своим собственным аккаунтом.

Админ видит и может управлять всеми данными платформы (заказы, профили, переписка, жалобы) — это не ограничено владением конкретной записью, в отличие от обычных пользователей.

---

## Доступные инструменты в админ-панели

| Раздел | Что доступно |
|---|---|
| Users | Просмотр всех пользователей, статус (активен/заблокирован/ожидает) |
| Vocalists / Producers | Списки по ролям |
| Orders | Все заказы платформы, независимо от участников |
| Reports | Поступившие жалобы |
| Content Moderation | Очередь модерации (демо, профили, ссылки) |
| Messages | Переписка пользователей (для разбора жалоб) |
| Settings | Настройки платформы |

---

## Как обрабатывать жалобу

1. Жалоба попадает в раздел Reports со статусом "open".
2. Прочитайте описание жалобы и, если необходимо, откройте связанную переписку (раздел Messages) для контекста.
3. Свяжитесь с обеими сторонами при необходимости уточнения деталей.
4. Примите решение (см. ниже категории нарушений).
5. Отметьте жалобу как "resolved" с кратким резюме принятого решения (для истории — на случай повторных обращений).### Категории нарушений и реакция (черновик — требует финального решения команды)

> ⚠️ **Этот раздел — предложенный каркас, не финальная политика.** Окончательные формулировки правил, пороги "сколько предупреждений до блокировки" и тон коммуникации с пользователем должны быть утверждены Галиной/командой, прежде чем использоваться как реальный регламент. Ниже — структура для обсуждения, не готовая к применению инструкция.

| Нарушение | Возможная реакция |
|---|---|
| Недостоверная информация в профиле (фальшивые демо, ложный опыт) | Предупреждение → при повторе блокировка |
| Грубое/неуважительное поведение в переписке | Предупреждение → при повторе блокировка |
| Подозрение на мошенничество (попытка увести оплату за пределы платформы с обманом) | Требует индивидуального рассмотрения — пока нет системы оплаты на платформе, риск ниже, но переписка с просьбой "заплати мне напрямую, а не через сайт" — сигнал к проверке |
| Спам / реклама не по теме | Удаление контента, предупреждение |
| Невыполнение заказа без объяснения (вокалист пропал) | Пока нет системы возврата средств — фиксируется как репутационный фактор; полноценная политика появится вместе с оплатой |

### Что НЕ решено и требует обсуждения до реального запуска

- Чёткие пороги "сколько предупреждений = блокировка" — сейчас не определено численно.
- Политика возврата средств и удержания оплаты при споре (зависит от выбора платёжной системы — Stripe Connect, и от того, как будет устроено escrow, если оно будет).
- Юридические формулировки (Terms of Service, Privacy Policy) — этот документ описывает только рабочий процесс модерации, не заменяет юридические документы платформы.

## Технические напоминания для админа

- Все изменения роли пользователя (например, выдача роли admin) — через Supabase Table Editor, не через код приложения.
- Блокировка пользователя — текущий механизм через таблицу `users`, статус (`status` в `AdminUserRecord`) — уточнить актуальную реализацию у разработчика перед использованием в реальной ситуации, раз эта часть миграции на Supabase ещё не завершена на момент написания этого документа (28.06.2026).

Этот документ, а также сам доступ к админ-панели, содержат конфиденциальную информацию о пользователях платформы (переписка, личные данные, заказы, разбор жалоб).

**Если роль администратора передаётся наёмному сотруднику** (не основателям/совладельцам проекта) — перед предоставлением доступа должно быть подписано соглашение о неразглашении (NDA). Этот раздел — организационное напоминание, не юридический документ.

> ⚠️ Текст самого NDA-соглашения должен быть составлен или проверен юристом, либо взят из надёжного проверенного шаблона — это не должно основываться на черновике, сгенерированном без юридической экспертизы. Если нужен черновик для отправки юристу на проверку — это можно подготовить отдельно, но финальный документ для подписания должен пройти юридическую проверку перед использованием.
